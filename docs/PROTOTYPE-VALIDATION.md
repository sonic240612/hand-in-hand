# 프로토타입 검증 기록

검증일: 2026-09-11. Windows, Node.js 24.11.1, Codex CLI 0.153.4.

## 실제 AI로 확인한 핵심 동작

**두 개의 독립 실행기가 A → B → A 순서로 같은 네이티브 Codex 세션을 재개했다.** 세 실행 모두 원래의 native thread ID를 유지했고, 호스트는 매번 새 원본이 기존 원본을 변경 없이 포함하는지 확인했다.

1. A가 파일에 없는 고유 문구 `violet-orbit-542`를 대화에서 지정했다. 호스트 파일 도구로 `host-only-7319`라는 영수증 값을 읽었다. 문구와 영수증을 새 파일로 저장하지 않도록 했다.
2. B가 별도 실행 프로세스에서 같은 세션을 재개했다. 도구를 사용하지 않고 이전 문구·영수증을 답했으며, 문구를 `amber-orbit-914`로 변경했다.
3. A가 다시 새 프로세스로 같은 세션을 재개했다. B가 변경한 문구와 최초 도구 결과를 이용해 호스트의 `result.json`을 작성하고 JSON 파싱을 검증했다.

최종 파일은 다음과 같았다.

```json
{
  "passphrase": "amber-orbit-914",
  "receipt": "host-only-7319"
}
```

실행 명령은 `npm run test:live`이며, 기계 판독용 결과는 `.research/live-report.json`에 저장했다. 이 실험에서는 본인 PC의 **한 로그인 계정**을 독립 실행기 두 개가 사용했다. **서로 다른 계정의 원본 재개, 계정별 할당량 분리, 두 물리 기기 사이의 연결은 미검증**이다. 계정별 인증과 원격 연결 경로는 구현했지만 이 실험만으로 공급자 측의 계정 간 호환성을 입증하지 않는다.

## 자동 검증

`npm test`로 다음 8개 시나리오가 통과했다.

- A → B → A의 FIFO 실행, 동일 ID, 지시·도구 호출/결과·수정 기록 보존.
- 인계 요약 대체, 과거 기록 수정, 다른 native ID, 압축 기록 차단.
- 같은 제출 ID의 중복 실행 방지, 호스트 재시작 시 미확정 턴 차단.
- 현재 사용자 지시가 빠진 원본 반영 거절.
- 일회용 초대·연결 코드, 사용자·실행기·실행 권한 검사, 권한 회수.
- 파일 hash 충돌, 경로 이탈·비밀 경로·junction 차단.
- 프로젝트 코드를 실행하지 않는 JavaScript 구문 검증.
- 다른 웹사이트에서의 bootstrap 요청 차단과 비공개 파일의 정적 제공 차단.

## 브라우저 확인

로컬 UI에서 현재 Codex 연결, 지시 제출, 호스트 파일 도구 결과, AI 응답과 완료 상태, native ID·원본 hash 표시를 확인했다. 실행 중 새로고침 후에도 같은 턴이 이어졌고, 완료된 턴은 세션 v1로 표시되었다. 호스트 서버를 종료·재시작한 뒤에도 동일한 native ID·원본 hash·완료 기록을 유지했고, 로컬 Codex를 다시 연결했다. 실제 샘플 `workspace/index.html`은 별도 샌드박스 iframe에서 표시된다.

초대·참여·일회용 코드 경로는 격리된 자동 테스트로 검증했다. 실행 중인 앱에서 실제 초대 버튼을 누르는 최종 UI 검사는 자동 승인 검토가 접근 자격 발급 위험을 이유로 거절하여 수행하지 않았다. 실제 초대 링크 발급과 다른 기기의 참여는 후속 확인 항목이다.

## VPN 없는 중계 추가 검증

`npm test`가 기존 8개와 중계 경로 3개를 합쳐 **11개 통과**했다. 임시 데이터 폴더에서 실제 중계 서버와 호스트 서버를 띄우고, 다음을 HTTP 왕복으로 확인했다. 이 검증은 AI 모델을 흉내 낸 테스트 기록을 사용하며 추가 Codex 호출은 하지 않았다.

- 초대 없는 대화·파일 조회 거절, 원격 소유자 자동 로그인 거절, 위조 proxy 헤더와 원격 로컬 Codex 연결 차단.
- 일회용 초대·참여자 실행기 연결, 같은 요청 중복 방지, 호스트 파일 실제 변경, native 세션 원본 저장.
- SSE 응답 전달과 참여 권한 회수 후 브라우저·실행기 접근 차단.
- 중계 오프라인 응답, 인터넷 HTTP 주소 거절, 임의 대상 경로 거절.

권한 회수 직후 종료된 SSE에 재전송하던 오류를 발견해 수정했다. 공용 HTTPS 배포, 실제 두 기기 사이 통신, 인터넷 장애 복구는 아직 별도 확인이 필요하다. 자세한 구조와 배포 준비는 [원격 접속 안내](REMOTE-ACCESS.md)에 정리했다.

## Tailscale 추가 검증

2026-09-11: 기존 11개와 Tailscale 관련 5개를 합쳐 **자동 테스트 16개 통과**. CLI 응답을 통제한 상태에서 다음을 확인했다.

- 기존 Serve 포트 보존, 포트 충돌과 Funnel 공개 설정 거절, 이전 앱의 소유 기록을 통한 대상 갱신.
- 설치 없음·미로그인·Windows 권한 문제·HTTPS 사전 설정 안내. 상태 확인 중 연결 요청 누락 방지와 설정 안내 유지.
- 연결 준비 전 초대 거절, 사설 HTTPS 주소로 초대 발급, 초대한 참여자의 같은 호스트 세션·파일 조회.
- 프록시로 들어온 원격 요청의 소유자 자동 로그인·로컬 Codex 연결·Tailscale 설정 변경 거절.

실제 PC의 Tailscale 1.102.2 설치와 Running 상태를 확인했다. 기본 포트 8443에 다른 Serve 서비스는 없었다. 사용자가 Tailscale 웹 관리자에서 HTTPS 사용을 허용한 뒤 앱의 Serve 연결이 정상 활성화되었다.

**2026-09-11 10:47 UTC 실제 HTTPS 왕복 검증 통과.** `node scripts/check-tailscale.mjs`로 유효한 TLS 인증서가 있는 사설 주소에서 다음을 확인했다.

- 공개 health 응답 200, 인증 없는 세션·파일 요청 401.
- 원격 소유자 자동 로그인 403(별도 HTTP 검사).
- 기존 소유자 인증으로 동일 native ID·원본 checksum·저장 버전 조회.
- 원격 요청에서 로컬 Codex 연결과 네트워크 관리 권한이 비활성화됨.
- 호스트 파일 목록과 실제 SSE 첫 상태 응답 수신.

결과는 `.research/tailscale-report.json`에 저장했다. 이 검증은 기존 소유자 권한으로 읽기만 수행했으며 초대 링크나 AI 턴을 새로 생성하지 않았다. 실제 Tailscale Serve를 통과했지만 **동일 호스트 PC에서 사설 주소로 접속한 검사**이므로 별도 계정·물리 기기의 공유 초대 수락과 접속은 후속 검증 대상이다.

로컬 브라우저를 새로고침하여 **Tailscale 연결됨** 표시를 확인했다. 기존 native ID와 저장된 턴 1개는 서버 재시작 후 유지되었다. 실제 ID·주소를 포함하는 로컬 검사 보고서는 저장소에 포함하지 않는다.

## 데스크톱 앱 쓰기 잠금 충돌 수정

2026-09-11: 사용자 테스트에서 호스트 → 다른 계정으로 보고된 참여자 → 호스트 순서로 이어갈 때 `already has an active writer (-32600)`가 발생했다. Windows 파일 점유 조회로 Codex 데스크톱 앱이 기본 저장소의 해당 세션 잠금을 보유한 것을 확인했다. host v3 원문은 정상이며, 오류 요청은 `thread/resume`에서 거절되어 AI 응답·도구 실행·새 기록이 없었다.

- 연결기별 `codex-runtime/`에 세션·DB·쓰기 잠금을 격리한다. 데스크톱 앱의 프로세스나 잠금 파일은 건드리지 않는다.
- 공식 로컬 ChatGPT 로그인 접근 토큰은 App Server의 외부 토큰 인증으로 메모리에만 전달한다. 갱신은 공식 Codex에 맡기며 API 키는 차단한다. 파일 기반 로그인이 필요하다.
- 자식 프로세스가 완전히 종료된 뒤에만 다음 실행으로 넘어간다.
- 실행 전 쓰기 충돌만 재시도 대상으로 분류한다. 구버전의 해당 중단 상태는 원문·버전·도구/응답/적용 여부를 검사하고 전체 상태를 백업한 후 해제한다.
- 재시도는 원래 작성자만 요청할 수 있고, 중복 클릭은 같은 재요청을 반환한다. 실행 이후 오류·시간 초과·기록 변형은 계속 차단한다.

**자동 테스트 24개 통과.** 실제 데스크톱 잠금이 유지된 상태에서도 격리 실행기가 동일 ID와 동일 원문 해시로 복원되었다. 이 복원 검사에서는 AI 턴을 실행하지 않았다.

이후 UI의 **다시 실행**으로 막혔던 기억 확인 요청을 한 번 실행했다. AI는 다른 참여자가 보낸 두 메시지를 정확히 회상했다. v3 → v4에서 세션 ID, 원문 전체 접두부, 이전 완료 턴이 모두 보존되었고 파일 도구 호출은 없었다. 이 요청은 로컬 ChatGPT 계정을 사용했으며 별도 API 키를 사용하지 않았다. 실행기 폴더에 `auth.json`이 생성되지 않은 것도 확인했다. 로컬 결과는 `.research/writer-recovery-report.json`에 보관한다.

저장된 실행기 계정 식별자는 두 종류였다. 이는 서로 다른 계정으로 보고된 실행기 간 대화 재개의 근거이며, **공급자 측 각 계정의 실제 할당량 차감은 아직 측정하지 않았다.** 위의 초기 동일 계정 실험과 구분한다. 호스트는 수정 버전으로 재시작했고 참여자용 ZIP도 갱신했다.

관련 공식 인터페이스: [App Server 인증](https://learn.chatgpt.com/docs/app-server#authentication), [Codex 저장 위치 환경 변수](https://learn.chatgpt.com/docs/config-file/environment-variables).

## 정상 컨텍스트 압축과 구버전 중단 기록 복구

2026-09-11: 다른 기기의 Codex CLI 0.154.0에서 v4를 적용한 직후 압축 감지 오류가 보고됐다. 연결기가 `contextCompaction` 이벤트를 무조건 중단하고, 호스트가 모든 `compacted` 기록을 거부하던 동작을 수정했다. 같은 모델로 바꾸는 것만으로는 로컬 0.153.4·0.154.0에서 자동 압축이 재현되지 않아, 해당 Mac에서 압축을 시작한 구체적인 조건은 확정하지 않았다.

Codex 0.154.0의 정상 압축은 기존 JSONL 원문을 변경하지 않고 같은 세션에 `compacted`와 컨텍스트 창 연결 정보를 추가했다. 이를 검증한 뒤 저장·교대를 허용한다. AI는 Codex가 관리하는 압축된 컨텍스트를 사용하고, 앱은 이전 원문도 계속 보관한다.

**자동 테스트 32개 통과.** 정상 압축 저장과 다음 참여자에게 전달, 잘못된 창 연결·과거 기록 변형 거절, 압축 이벤트에서 강제 중단하지 않음, 구버전 차단 기록의 작성자 제한·원문 및 중단 확인·백업·중복 복구 거절을 추가로 검사했다. AI 응답·도구 호출·다른 지시·중단 증거 누락이 있으면 복구가 거절된다. 구버전 실행기는 등록 단계에서 업데이트를 안내하여 같은 오류의 반복 실행을 막는다.

실제 CLI 0.154.0으로 호스트 v4의 **별도 복사본**에서 자동 압축 임계값을 낮춰 압축을 유도했다. 수정 연결기가 압축을 중단하지 않고 턴을 완료했고, 별도 실행 저장소로 다음 턴을 재개했다. 두 응답 모두 프로젝트 이름 “두손”을 회상했고, 두 실행 모두 같은 native ID와 이전 원문 전체 접두부를 유지했다. 이 검증은 한 ChatGPT 계정을 사용했으며 API 키를 사용하지 않았다. 실제 호스트의 v4와 차단 상태는 변경하지 않았다. 결과는 로컬 `.research/compaction-continuation-report.json`에 보관했다.

Mac의 기존 실패 턴 복구 파일을 업데이트한 연결기가 인증된 호스트로 전달했다. 최초 검사는 Codex 자체 `<turn_aborted>` 안내가 `user` 메시지로 저장된 형식을 다른 지시로 오인했다. 확인되지 않은 후보를 활성 세션과 분리해 보관하고 검사한 결과, 추가 기록은 실행 설정·시작·자체 중단 안내·같은 턴의 중단 확인뿐이었고 AI 응답과 도구 실행은 없었다.

`generic.turn_aborted` 메타데이터, native turn ID, 메시지 형식을 함께 확인해 해당 안내를 허용하도록 수정했다. 다른 턴의 안내·임의 사용자 지시·AI 응답·도구 호출은 여전히 거절된다. **실제 Mac 원본을 백업하고 v4 → v5로 복구했으며, 원래 native ID와 이전 원문 전체를 보존했다.** 로컬 결과는 `.research/mac-recovery-report.json`에 저장했다.

사용자가 Mac에서 연결기를 재시작하고 같은 요청을 다시 실행했다. **실제 압축 1회를 거쳐 v5 → v6 저장을 완료했다.** 같은 Mac 작성자와 native ID를 유지했고, 복구된 v5 원문 전체가 변경 없이 포함됐다. 응답은 다른 참여자가 프로젝트 이름을 “두손”으로 정하고 `index.html` 설명을 요청했던 지시를 회상했다. 차단은 해제 상태이며 도구 실행은 없었다. 검증 결과는 `.research/mac-continuation-report.json`에 보관했다.
